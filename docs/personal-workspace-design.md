# 个人资料库 Workspace 基础能力设计

## 1. 阶段目标

本阶段将 Hex Workspace 建设为个人资料库：用户注册后直接获得唯一的个人 Workspace，并能在其中通过目录树管理文件夹和云文档。

本阶段只解决个人资料的组织、创建、上传和管理，不引入协作者、分享、访问申请或资源权限。

## 2. 核心产品语义

### 2.1 个人 Workspace

- 每个用户只能拥有一个 Workspace，即注册时由系统分配的默认个人资料库。
- 用户不能主动创建第二个 Workspace。
- 默认 Workspace 不能被删除，也不能转让所有者。
- 用户注册、默认 Workspace 创建和根目录创建应处于同一个事务边界，避免产生没有资料库或没有根目录的用户；同一用户的初始化过程必须串行化，重复请求只复用既有 Workspace 与根目录。
- Workspace 当前只表达个人资料的归属和隔离，不表达团队、组织或成员关系。

### 2.2 根目录

- 每个 Workspace 必须有且只有一个根目录。
- 根目录由系统创建，用户不能删除、移动或修改其父目录。
- 用户创建的文件夹和云文档最终都属于这棵目录树。

### 2.3 统一资源

Workspace 内只向产品层暴露两类资源：

```text
Workspace
└── RootFolder
    ├── Folder
    └── CloudDocument
```

- `Folder`：用于组织目录层级。
- `CloudDocument`：平台统一管理的文档，来源可以是平台新建或本地上传。
- 本地内容导入后不在产品和领域层形成独立的 `File` 资源；内部内容快照只能依附于 CloudDocument 版本。

## 3. 文件夹能力

本阶段支持：

- 新建文件夹。
- 查询文件夹及其直接子资源。
- 修改文件夹名称。
- 在当前 Workspace 内移动文件夹。
- 逻辑删除文件夹及其子资源。

约束：

- 文件夹不能移动到自身或自己的任意子目录中。
- 不支持跨 Workspace 移动。
- 删除文件夹表示整棵子树进入已删除状态，不立即物理清理文档内容或对象存储文件。
- 根目录不能执行重命名、移动或删除操作。

## 4. 云文档能力

### 4.1 文档来源

CloudDocument 有两种来源：

1. `PLATFORM_CREATED`：用户在平台中直接新建。
2. `LOCAL_UPLOADED`：用户从本地上传后转化为平台级云文档。

两种来源进入 Workspace 后使用同一套目录、重命名、移动和删除能力，不再以“文件”和“文档”区分产品操作。

### 4.2 平台新建

- 平台当前只允许新建 Markdown 文档。
- 新建文档默认使用 `.md` 后缀。
- 新建时创建稳定的 Document 身份和版本 1；内容允许为空。
- 编辑 Markdown 内容时创建新版本，不直接覆盖旧版本。

### 4.3 本地上传

- 本阶段允许上传任意文件格式，不受现有 RAG 解析格式限制。
- 上传成功后直接创建 CloudDocument，不形成第三种独立资源。
- CloudDocument 的版本内容快照保存原始名称、后缀、MIME、大小、内容哈希及对象存储定位信息。
- 上传内容作为文档版本 1 保存，来源标记为 `LOCAL_UPLOADED`。
- 上传是否成功与文档能否解析、检索或在线编辑相互独立。
- Markdown 云文档支持平台内编辑；其他格式当前只支持查看元数据、重命名、移动和删除，待后续接入对应编辑器。

### 4.4 基础操作

本阶段支持：

- 新建 Markdown 云文档。
- 上传本地文件并创建云文档。
- 查询云文档详情和当前版本内容。
- 编辑 Markdown 云文档内容。
- 修改云文档名称。
- 在当前 Workspace 内移动云文档。
- 逻辑删除云文档。

不支持：

- 在线编辑非 Markdown 文档。
- 跨 Workspace 移动。
- 文档复制。
- 版本历史列表和版本恢复。
- 批量上传本地文件夹。

## 5. 名称与重名规则

同一父目录下按“资源类型 + 完整名称”判断冲突：

- 两个文件夹不允许使用完全相同的名称。
- 两个云文档不允许使用完全相同的文件名，包括后缀。
- 基础名称相同但后缀不同的云文档可以共存，例如 `方案.md` 和 `方案.pdf`。
- 文件夹和云文档可以使用相同展示名称，因为资源类型不同。
- 移动和重命名也必须执行相同的冲突检查。
- 文件名比较是否区分大小写由数据库规则统一决定；当前建议不区分大小写，避免不同操作系统产生不可预期的冲突。

## 6. 删除语义

本阶段所有删除均为逻辑删除：

```text
ACTIVE → DELETED
```

- 删除资源后，常规目录查询不再返回该资源。
- 删除文件夹时，其全部后代资源必须在同一业务操作中进入已删除状态。
- 本阶段不提供回收站列表、恢复和永久删除接口，但数据模型需要保留后续实现空间。
- 对象存储内容暂不随逻辑删除立即清理。

## 7. 本阶段业务边界

### 包含

- 用户注册时创建唯一的默认 Workspace。
- 为默认 Workspace 创建唯一根目录。
- 目录树和直接子资源查询。
- 文件夹的新建、重命名、移动和逻辑删除。
- Markdown 云文档的新建、读取、编辑、重命名、移动和逻辑删除。
- 任意格式本地文件上传并转换为云文档。
- 文档导入失败后的对象存储孤儿内容清理。
- Workspace、目录和文档之间的归属一致性校验。

### 不包含

- 多 Workspace。
- 团队、成员或协作者。
- `VIEW`、`EDIT`、`MANAGE` 等资源权限。
- 手机号邀请、链接分享和访问审批。
- RAG 解析、分段、索引和检索改造。
- hexgent、任务编排和文档自动编辑。
- 非 Markdown 在线编辑器。
- 本地文件夹批量导入。
- 回收站恢复和永久删除。

## 8. 实现约束

- 现有“创建 Workspace”接口应移除或关闭，不能只依赖前端隐藏。
- 领域模型中不再以 File 作为用户可操作资源；底层二进制对象及其当前定位信息直接依附于 Document。
- 所有目录写操作必须校验目标资源和目标父目录属于同一 Workspace。
- 移动文件夹前必须检查目录环路。
- 长流程编排方法应使用有序中文步骤注释，说明校验、持久化和清理顺序。
- RAG 可以继续读取 CloudDocument 的版本内容，但不能反向限制允许上传的文件格式。

## 9. 验收标准

完成本阶段后，应能验证以下主流程：

1. 新用户注册后自动获得一个且仅一个 Workspace 和一个根目录。
2. 用户无法创建第二个 Workspace。
3. 用户可以在任意有效目录下创建、重命名、移动和删除文件夹。
4. 用户可以新建并编辑 Markdown 云文档，编辑后产生新版本。
5. 用户可以上传任意格式文件，上传成功后目录中出现对应 CloudDocument。
6. `方案.md` 与 `方案.pdf` 可以位于同一目录，两个 `方案.md` 不可以。
7. 文件夹不能移动到自身或子目录，资源不能跨 Workspace 移动。
8. 删除文件夹后，其全部后代资源不再出现在常规查询中，底层对象不会被立即物理删除。
